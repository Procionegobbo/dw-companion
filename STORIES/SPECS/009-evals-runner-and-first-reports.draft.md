**Status:** draft — to be expanded by spec-builder.

## Scope

- `evals/datasets/router.jsonl` (~40 cases), `rules_qa.jsonl` (~40 cases, with
  `expected_section_ids` and `key_facts`, including unanswerable questions),
  `move_classification.jsonl` (~80 cases, `expected_move_id`/`no_move`,
  `acceptable_alternatives`, covering every basic and special move, ambiguous pairs like
  Defy Danger vs Hack and Slash, and at least 15 `no_move` cases) — per the exact shapes in
  section 6.1.
- Metrics per section 6.2: router accuracy + confusion matrix; retrieval recall@k; rules
  answers' citation validity rate (deterministic), key-fact coverage (LLM-as-judge, judge
  model different from the answer model), correct refusal rate; move classification
  accuracy, confusion matrix, `no_move` precision/recall, clarification rate; system
  latency p50/p95 and tokens/cost per query per intent.
- `evals/run.py` CLI: runs a dataset against a named config, writes
  `evals/reports/<date>-<config>.json` + markdown summary. Every run traced in Langfuse
  with the config as metadata.
- CI: `workflow_dispatch` manual trigger (optionally weekly), with a hard budget guard that
  aborts if estimated cost exceeds a threshold.

## Critical rule — do not skip

**Labels are written or validated by the project owner** (an experienced GM), never
generated by the model under test. Agents may draft candidate cases, but every label needs
human review before it enters a dataset; each row carries `reviewed: true`, and the runner
refuses unreviewed rows.

**Per the handoff's own instruction for this milestone: pause here and have the owner
review and label the datasets before trusting any number.** Drafting unreviewed datasets and
wiring the runner is in scope for a feature-builder story; treating any metric as meaningful
before the owner has reviewed/labelled the rows is not — flag this explicitly rather than
silently proceeding to spec 010 with unreviewed numbers.
